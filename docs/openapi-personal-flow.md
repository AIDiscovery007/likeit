# 个人开发者真实歌词闭环补充契约

用户确认官方个人开发者入口、提供自有凭据并完成手机扫码。主会话真实请求证据：两个HTTPS网关均接受同一用户token并返回相同目标命令描述；搜索仅传keyword/limit时HTTP400空body，补上清单明确的offset=0、qualityFlag=false、trialScene=cli后业务200。`data.records`每行有独立数字originalId与32hex字符串id；已精确命中用户提供的Popular数字ID。逐字接口业务300“应用未授权当前接口”；清单声明的普通歌词接口业务200，原文79个时间标记。真实响应和凭据只在仓库外。

本补充基于已观察到的协议，扩展支持范围，不修改原冻结文件，不把授权失败改判为无歌词。

## 固定行为

- 参数取值优先级：固定值、调用方提供值、清单非null默认值。只有声明的受支持标量参数可发送；沿用全部类型、required、路径、host、identity校验。调用方keyword和limit=20覆盖默认值；false及0保留。选中默认值类型不符时拒绝；缺少默认值仍按原required规则处理。
- 新增 `data.records` 这一已证实容器。仅该格式允许其独立32hex `id` 字段作为加密歌曲ID，前提是显式originalId与已验证数字ID精确相等。仍拒绝缺原始ID、数值id、冲突加密字段/配对，禁止用id冒充originalId或转换/猜测ID。既有songs/list规则保持。
- 私密配置新增可选 `lyricSource`，仅支持 `word`、`standard`。缺省为word，所有原有逐字优先、无逐字再普通的行为及错误规则保持。显式非法值、null、非字符串均配置失败。
- 显式standard时，manifest → 官方精确搜索映射 → manifest声明的song lyric，跳过逐字接口，返回同步原文。普通接口授权错误仍明确失败，不尝试逐字或公开接口。word模式的授权错误同样保持失败，不做静默降级。
- 沿用原取消、迟到保护、超时、体积上限、配置安全和元数据匹配提示；不更改旧公开resolver，不自动登录/刷新、不打印秘密、不更改音乐状态。

主会话预先新增并运行11条行为检查（Node含父项12 tests），只用公开生成测试key和裁剪命令清单，无真实网络。开发者只写实现、构建、lint并提交，不写改跑测试。用户本机验证使用standard，因其实际授权普通歌词；逐字权限需另行开通，不能宣称已接通逐字接口或逐字高亮。
