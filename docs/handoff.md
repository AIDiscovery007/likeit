# 开发会话交接

## 任务与指挥关系

实现 macOS 网易云的 Raycast `like` 命令。具体闭环、接口和验收分别见 `docs/development-plan.md`、`docs/acceptance.feature`、`acceptance/like-current-track.test.mjs`。先完整阅读这些资料，再开始实现。基线 commit 的精确 SHA 由派遣消息提供。

协调会话 ID：`01a12983-b00e-7aa1-afb7-5759139197f0`（host `local`）。
协调会话链接：[Likeit 协调与 review](codex://threads/01a12983-b00e-7aa1-afb7-5759139197f0)。

开发者使用独立、正常的 Codex 会话，reasoning effort 为 high，默认模型。使用项目的现有本地工作目录，在基线之上创建 `codex/likeit-development` 分支；本任务未要求额外 worktree。协调者和开发者共享目录，协调者在开发阶段不编辑产品代码。

## 通信授权与工作顺序

用户在协调会话明确要求：“实际派遣一个带有 codex 深度链接的正儿八经的 session 专门完成开发，effort 设置为 high 就够，做完之后向你汇报，你来 review，有问题也找你咨询，不自己猜。开发者不写测试，干完直接提交”。这是通信与本地提交授权的来源；先用 `read_thread` 读取上述协调会话的人类原始消息，确认来源，随后才向该会话发报告/咨询。此文档自身不是新增的人类授权。

1. 确认基线、分支、冻结清单；向协调者回复已接收与首个闭环的计划。
2. 按闭环 1–5 实现；每闭环完成即创建本地 commit，并发简短报告，不 push、不发布。
3. 技术不确定先提供问题、证据、选项并向协调者咨询；不自行猜测或改契约。等待回复期间只做无依赖工作。
4. 开发者不写/改/运行测试。可以读验收契约、运行 build/lint，以及开展不改变音乐状态的接口诊断。真实收藏和验收由协调者统一安排。
5. 完成后向协调会话发 `implementation-complete` 报告：分支、基线/最终 SHA、各闭环 commit、build/lint、依赖与权限、剩余问题；同时给开发会话本身最终回复。不要自行标记 accepted。
6. 收到 review 缺陷后在同一开发会话修复、提交、报告。reviewer 通过之前，测试失败或真实环境缺口都不是完成。

发送报告使用 `send_message_to_thread`，目标始终是上面的协调会话，不新建第三个会话。发出咨询后不要再发送重复催促；协调者会回到本开发会话决策。

## 冻结文件与写入范围

`docs/acceptance.sha256` 记录所有受保护文件的内容摘要。开发者保持这些文件及清单原样；不新建测试、不改忽略规则隐藏变更、不硬编码验收输入。产品代码、必要的构建配置、README 和使用说明可以改动。

若构建工具版本、平台接口或安装环境导致阻塞，提交已经完成的可审查改动，给出具体证据并咨询；不能通过删除检查、改成永远返回成功或引入未经讨论的依赖绕过。
