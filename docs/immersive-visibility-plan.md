# 可见性与焦点分离

用户明确确认“桌面仍可见就继续律动，真正隐藏、完全遮挡或退出时才停止”；这是本轮行为范围。基线51c68e231c67d6f843c4ba5f6987efdde50de6ac，已有344项验收、20份冻结清单保持原样。

根因已在生产DesktopMain.updateMotion确认：`NSApp.isActive && window?.occlusionState.contains(.visible) == true`把失焦当成不可见，连带停止音频与降低歌词刷新。应去掉焦点门禁，依据系统窗口遮挡状态，保留动效、播放、来源新鲜度及退出门禁。保留退出时原前台应用恢复判断中的NSApp.isActive，不应全局删除它。

修改限于DesktopMain的可见性判断、必要说明与同步原生产物；不加通用状态机、不改歌词provider、权限或签名策略。原开发会话high实现并提交，不写/改/编译/运行测试；协调者验收。

补充14项行为检查：直接提取并原样编译生产updateMotion方法，以无AppKit夹具提供焦点、遮挡、动效、播放和时间输入，观察实际采集意图/歌词刷新/律动输出。它不修改生产方法，也不把旧的焦点公式复制成测试判定。该测试不能证明系统遮挡事件实际交付；协调者另做真实小窗覆盖、恢复与退出检查。旧音频生命周期测试仍覆盖真实HAL隔离接口，全部保持不变。

验收顺序：先记录新增回归红灯并冻结；开发完成后复跑新增与旧验收、核对原冻结摘要及源码/包摘要，再安装验证。当前主分支已合入社区歌词，重新构建会同时包含它；本轮只验收可见性修复，不把社区歌词尚未验收的实机路径包装为通过。没有本机固定签名身份授权，不创建证书、私钥或更改TCC。
