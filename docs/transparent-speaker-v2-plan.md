# 全屏与歌词动效补充计划

用户 2026-10-11 明确纠正：“随歌词节奏的动态效果呢？？原 html 里是有实现的；还有需要改成全屏的透明音响实现，html的底色只是因为它是一个demo”。V1 的 858f715 是已集成中间态，不代表此次需求已验收。

本补充是用户纠正后的需求变更记录，不回写旧验收使实现通过。V1 文件、测试和冻结清单保持原样；本补充优先覆盖 V1 T06 固定 16:9 展示框及“静态背景即可”的设计，澄清 T08 音频失败只停音频响应、不能停有可信时间的歌词动效。其他契约继续有效。

## 视觉与动效决策

- 透明音响本体占满窗口，适应屏幕长宽比。删除 `palette.room` 外围房间背景、缩小面板计算与外部标题/页脚布局。玻璃场景是产品背景；不要求整个 macOS 窗口透出其他 app。窄边框贴四边，木色底沿位于屏幕底部，扬声器保持透明中心。
- 控件和歌曲/采集状态叠在玻璃上，留出稳定的歌词安全区域。800×600、1280×800、1920×1080 都要完整可用；长翻译与歌词不得压住扬声器和控件。
- 原 HTML 歌词 `.line` 用 220ms 淡入、500ms 小幅滑入（约歌词区域宽 2.5%，ease-out）。保留这一视觉意图；原 demo 的 BPM 定时显示不进入产品。换行只由真实歌词 cue 决定，旧行可短淡出但不能覆盖新行或延迟输入。实现可以用时间进度驱动或可中断原生过渡，不规定内部算法。
- 逐字高亮沿用原解析范围与时间；每 100ms 位置更新不重新触发整行入场。重复文字必须用歌曲、行索引和起始时间区别；seek/换歌立即追随最新行，不排动画队列。首次切入主题直接呈现当前位置，不补播此前歌词。
- 青瓷光斑移动/呼吸、条纹落日轻缩放、夜航星光与横向波纹、纸页条形响应必须看得到动态。幅度来自既有真实 low/mid/high；时间相位需要时只读取已验证播放位置，不另造 BPM 或常驻播放器时钟。三频段条形响应不可谎称完整 FFT 频谱。不接入示例 synth、随机输入或第二次采集。
- 音频数据归零/失败时场景和扬声器静态；真实歌词时间仍可驱动行/字效果。暂停、隐藏、来源失效、off、system+Reduce Motion 停止全部非必要运动，立即恢复完整可读文字。always 继续沿用现有明确覆盖系统策略的语义。
- 提供清楚可发现的主题键盘选择（Cmd+1 经典、Cmd+2 透明，可放原生菜单）；不改变系统键盘导航偏好。现有退出和重试保留。

## 窄的真实状态边界

在现有 DesktopView 三文件编译边界内保留真实模型，新加以下呈现数据，不创建播放器框架：

```swift
struct DesktopLyricCue: Equatable {
    let trackKey: String
    let index: Int
    let start: Double
}
// DesktopModel.lyricCue: DesktopLyricCue? = nil
// DesktopModel.lyricPosition: Double? = nil
// DesktopModel.motionEnabled: Bool = false
```

Session 普通/社区渲染使用真实 snapshot.key、index、line.time/start 和现有 playbackPosition 验证结果。没有可信位置时两个字段清空；首行前、纯文本、纯音乐无 cue；后两者仍可保留真实播放位置。清来源/停止清空二者。选择主题/场景不改这三个状态。

DesktopMain 的现有 allowAudio 表示策略、可见性、播放、新鲜度是否允许运动，并非已获权限或采集成功；同步该 gate 到 motionEnabled 即可。不以 audioStatus 文案解析权限。现有 immersive-visibility 测试会提取 updateMotion 到旧 fixture；在 allowAudio didSet 同步新字段可保留旧抽取边界，也符合生产状态单一来源。不得为加字段修改旧 fixture。

本次允许 DesktopSession 上述最小呈现数据改动；不改歌曲身份定义、provider、cache、匹配、TTML/LRC 解析、网络和采集模块。主协调会话已收到避让通知。

## 验收与证据边界

新自动测试由协调者预先编写并冻结，调用真实模型和实际 Session 渲染方法，隔离网易云/网络。视觉与动画是否可见需真实 View 图像/操作判断，不能用有字段或有 animation 修饰符冒充。离线输入标为 synthetic，不宣称验证了实机音频采集。

先运行新增测试及 theme/routing/highlight 定向回归，再运行 `node --test --test-concurrency=2 acceptance/*.test.mjs`。旧测试、断言、超时不改。静态矩阵包含长中英文/emoji/翻译、纯文本滚动、未知状态、四场景与三尺寸；动态矩阵包含行初始/中途/稳定、同句逐字推进、快速 seek、门控中止、真实频段输入前后/归零。

实机测试须独占 UI，不操作音乐播放、不更改权限或系统减少动态偏好。既有权限与真实播放能支持多少就记录多少；未执行条件明确写未验证，不冒充通过。最终还验证新安装 bundle 源码一致、主题持久化、快捷键、连续切换与退出。
