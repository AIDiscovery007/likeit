## Spec review

## 真实音频验收与异常调查

用户明确同意临时将桌面设为 always、系统提示时授予音频访问、播放当前歌曲，结束恢复 system 和暂停。主会话经 Raycast UI 将桌面设为 always；未操作收藏动效（当时截图显示收藏动效已为 always）。这轮没有新系统权限弹窗，也没有点击任何授权。

`6dce422` 的 PID 26733 实际显示“网易云实时音频律动”，该状态仅在收到非零 PCM 后产生。两次实际截图的左音响区域 682,500 像素中 100,551 发生变化，排除了歌词、进度和状态文字区域；结合生产数据路径和截图，证实真实音频与视觉更新，不能由此宣称每鼓点或 BPM 准确。

计划的 10 分钟采样在约 25 秒记录后中断，不能算长时性能通过。短样本 active CPU 约 39–45.5%、RSS 约 125–142 MiB；随后不活跃时下降。期间进程正常 terminate 并退出，后续 CUA 读取又启动了默认 off 的新进程。工具提示有用户操作，但用户明确否认，必须作为待查异常，不能归因人为退出。当前在做无 UI 操作对照和逐步重放；未找到 Likeit crash report。暂不把暂停、恢复和自然换曲这一轮标为通过。

进一步对照：PID 29199 在无 UI 操作的 20 秒内持续存活；正式入口重入 always 后收到 PCM，逐步执行只读网易 AX、展开 Controls、点击当时标为 Play 的命令，每步进程均存活，45 秒观察未复现退出。之后实际媒体为 Sweet Boy / Malcolm Todd（原始 get 只读确认），桌面清掉旧歌并更新元数据，但音频进入永久 failed 提示。该失败为明确待修风险；现有信息不能区分 start 系统调用错误与断流判定。正在独立临时副本准备有界事件诊断，正式源代码和冻结测试不变。

诊断实际定位：日志 `diagnostics-repro.log` seq21 主线程短暂失焦请求 nil，seq23 已恢复 P；seq26 仍执行旧 nil，销毁刚成功的 generation1。立即开始 generation2，createTap 返回 noErr + tap0，read-tap-format 返回 `!obj`（560947818）并永久 failed。旧 device150 回调随后迟到。这次没有 firstPCM、PCM-gap 或自动退出事件。系统 UI 只读确认 Likeit Desktop 的 System Audio Recording Only 开关为 on，不是可见的关闭权限状态。

协调者于修复前提交 `ae8067e`：独立补充 BDD 和16项 HAL 生命周期检查，新增4项冻结文件。未改生产源码，通过同模块 fixture 拦截外部 HAL，执行前 nm 守卫拒绝真实 HAL 调用。7项失败在三次独立运行中完全一致，9项通过；新增用例与原125项并存。开发者开始最新意图合并、无效句柄和旧 epoch 回调修复，暂不引入自动重试。

诊断版本次持续运行至主会话明确 Esc，日志 seq195 精确记录 escape、seq199 约55ms后正常终止。分步暂停后只读确认 Sweet Boy 于153.571814秒暂停，音乐已暂停。此前无法归因的退出仍未稳定复现，不能宣称已修复。临时诊断没有进入正式源码或正式提交，其 patch 仅作为审计证据保存；退出后停止日志流和开发 watcher 并恢复正式安装包。
