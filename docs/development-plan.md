# Likeit 开发与验收计划

## 目标与产品边界

用户在任意前台 app 中唤起 Raycast，输入 `like` 并回车，将网易云当前正在播放的歌曲加入“我喜欢的音乐”，随后回到原工作界面。首版仅 macOS 网易云音乐；暂停、来源或曲目不明确时提示原因，不启动播放、不收藏残留歌曲。已有喜欢只提示，不取消。客户端确认不等于云端同步。

现有只读证据见 `docs/feasibility.md`。后台菜单可读是事实；后台点击、歌曲身份、实际权限及 Raycast 完整调用链仍需验证。

## 角色、冻结与决策

- 协调会话（reviewer）：制定并冻结 BDD 和自动化验收，执行测试及真实环境验收，review 每个闭环与最终 diff，决定技术疑点。开发者不能自行调整产品语义。
- 开发会话：以 high effort 实现最小闭环、维护使用文档、运行构建/lint、提交代码并汇报。不编写或运行测试，不修改验收资料。
- 固定基线包含原始模板、此计划、BDD、自动化契约与 SHA-256 清单。review 先核对冻结文件，再运行原有验收；失败应修实现。
- 只有发现与原始用户意图矛盾的测试错误时，reviewer 才能提出单独的契约勘误，说明原断言、问题、正确预期和影响，先取得用户确认，再独立提交；不能用实现现状证明测试错了。新发现的问题可以补充 reviewer 所有的回归检查，不得削弱旧检查。
- 真实环境无法覆盖的项目标为“未验证/阻塞”，不得用 mock 或 build 通过替代。`implementation-complete` 与 `accepted` 分开记录。

## 最小闭环

| 闭环 | 开发交付 | reviewer 的闭环验证 | 完成条件 |
| --- | --- | --- | --- |
| 0 基线 | reviewer 先提交计划、BDD、自动化验收与冻结清单 | 在模板上运行验收，记录预期红灯 | 固定 baseline SHA，开发尚未开始 |
| 1 只读状态 | 一个网易云读取入口：运行、播放、喜欢、曲目身份、权限；可有只读诊断脚本 | 比较真实网易云状态与输出，检查后台不激活、未知值不伪造 | 状态证据与局限报告；身份或后台语义未知先咨询，不能假定已完成 |
| 2 行为决策 | 独立且很小的 `likeCurrentTrack` 流程，拒绝不可操作状态、执行前复查、执行后确认 | 固定自动化场景（不触碰音乐 app） | 所有核心 BDD 自动化检查通过；开发者提交后由 reviewer 运行 |
| 3 原生收藏 | 原生 adapter 只执行语义明确的 Like；动作前在原生侧复查身份、播放和喜欢状态 | 真实未喜欢/已喜欢、后台、最小化、无窗口、换歌；记录动作和结果 | 不抢焦点、不取消喜欢；拿不到可靠身份时返回不可操作并咨询，不能宣称主路径成功 |
| 4 Raycast 集成 | macOS/no-view/like 搜索关键词、HUD、权限引导、超时、跨进程互斥与异常反馈 | 从真实 Raycast 进入，连续/并发触发、权限失败、超时及焦点 | 普通用户路径完整；重叠调用最多一个写入；关键词与可选 alias 说明准确 |
| 5 交付 | README、依赖与权限说明、已知限制；最终本地 commit；结构化汇报 | 固定测试、build/lint、契约完整性、代码规范与需求 review | reviewer 出具 accepted 或具体缺陷/阻塞；有缺陷回到同一开发会话修复 |

闭环按顺序实现，但允许在上一闭环等待 reviewer 决策时开展无依赖的文案/入口工作。每个闭环都提交可审查的最小改动；代码已提交不代表验收已通过。

## 最小实现边界

保留两个必要边界即可：不依赖 Raycast/原生进程的行为流程，以及网易云的真实读写 adapter。Raycast 入口负责用户反馈和运行互斥。具体文件拆分由开发者决定，避免多播放器注册器、常驻监听服务、AI、坐标点击及未核实的网络接口。

优先尝试 `runAppleScript` + System Events，原生 AX helper 是证据支持下的后备方案。新增原生打包方式、外部二进制或 MediaRemote 依赖前向 reviewer 咨询，说明证据、权限、维护和分发成本。最终用户不应安装 Xcode 或在首次运行时编译源码。

歌曲身份优先采用 app 暴露的真实 ID。其他稳定元数据组合须给出来源和稳定性证据并由 reviewer 确认。曲名、静态常量、菜单标题、播放按钮、当前前台 app 不能单独冒充可靠身份。读不到身份则返回不可操作；不能把缺失身份的失败路径包装成完成了收藏功能。

点击前后身份复查只降低竞态，不能声称原子绑定歌曲。可观测到的换歌必须停止或反馈“结果未确认”；底层检查与动作之间的剩余竞态应明确记入限制。

## 自动化验收入口契约

`src/like-current-track.ts` 导出 `likeCurrentTrack(port)`，只使用可被 Node 24 直接执行的 TypeScript，不导入 Raycast 或原生进程模块。该边界用于检验用户行为；不规定内部算法、类结构或 adapter 实现。

```ts
type Snapshot = {
  state: "playing" | "paused" | "not-running" | "unknown" | "permission-required";
  trackKey: string | null;
  liked: boolean | null;
  title?: string;
};
type Port = {
  read(): Promise<Snapshot>;
  pressLike(expectedTrackKey: string): Promise<"pressed" | "already-liked" | "changed" | "unavailable">;
};
// 返回 { status: string, title?: string }；状态含义由固定测试与 BDD 定义。
```

`pressLike` 的真实实现必须在原生侧复查当前歌曲和菜单语义；`pressed` 仅代表动作已发出，流程仍需读取相同歌曲的 liked=true 才能返回 `liked`。动作发出后通信异常一律结果未确认，不重试点击。流程允许有界只读轮询确认，但遇到歌曲变化即停止，不能持续点击。

自动化命令：`node --test acceptance/like-current-track.test.mjs`。此套测试只证明流程行为，不能证明 AX、权限、跨进程锁、真实播放状态或云端成功。真实层必须独立验证。

## reviewer 测试范围与取证

| 层次 | 固定范围 | 通过证据 |
| --- | --- | --- |
| 自动化核心 | 首次喜欢、已喜欢、未运行、暂停、未知、缺权限、缺身份、读失败、前后换歌、状态变化、adapter 拒绝、动作结果未知、不得二次点击 | 原始 Node TAP 输出、commit SHA、冻结 SHA-256 校验 |
| 静态/构建 | macOS 单平台、no-view、like 关键词、移除 AI 模板；build、lint；无凭据读取、无坐标/盲键盘 toggle | 命令输出与真实 diff |
| 原生集成 | 中英文菜单与状态刷新；未喜欢/已喜欢；真实 ID 与显示歌曲一致；app 后台/最小化/无窗口；不可收藏内容 | 输入状态、操作次数、前后客户端状态与焦点；不能以脚本退出码替代 |
| Raycast 端到端 | 任意前台 app、另一 app 全屏/Space、权限缺失/撤回、重复与并发调用、异常退出后恢复、超时、暂停、网易云未运行、其他 app 正在播放 | 实际从 Raycast 启动的记录；HUD 文案及是否切换焦点 |
| 账号与网络 | 未登录、离线或网络失败的诚实反馈；客户端收藏和云端同步区分 | 真实可用证据，否则标记未验证；不为了制造用例更改用户网络或账号 |

真实音乐状态变更由 reviewer 统一安排，开发者只做只读诊断。需要用户授权的系统权限由用户处理，不绕过权限。没有合适的当前未喜欢歌曲时先完成其他验证并报告缺口，不随机收藏、切歌或取消现有喜欢来凑测试数据。禁止声称“所有 app 同时播放自动识别”已经支持。

## 汇报格式

每次报告包含：闭环编号、commit SHA、修改路径、证据、未验证项、待决策问题。咨询必须提供实际观察、已排除原因和建议选项；收到 reviewer 回复后再做依赖该决定的变更。

最终报告使用 `implementation-complete` 标识，附所有 commit、build/lint 结果、实际依赖/权限、已知限制。reviewer 通过后另记 `accepted`；不由开发者给自己验收通过。
