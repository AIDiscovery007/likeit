# 歌词持久缓存增量计划

用户本轮明确要求减少每次重新匹配。此增量授权成功歌词内容持久化，替代旧社区计划的“不落盘”和官方handoff的“不缓存歌词”限制；不改旧冻结文件，不启用URLSession缓存，不缓存官方命令清单、凭据或失败结果。来源选择和严格歌曲匹配规则不变。

## 用户路径与边界

1. 首次完整身份匹配成功，显示歌词并保存解析后的成功内容。包括网易公开、网易官方、AMLL逐词/翻译、LRCLIB逐行/纯文本/纯音乐。
2. 同一首歌退出再打开，或媒体会话PID/opaque key改变：按完整标题、艺人、专辑、精确时长与来源策略读缓存，直接显示；命中不请求搜索/详情/歌词，也不闪现网络匹配状态。可标注“本地缓存”，保留原归属。
3. Live/Remix等版本名称、艺人、专辑、时长、可信网易ID输入或来源策略改变，不复用旧内容。字段不完整不命中。缓存身份不采用播放器临时key。
4. 官方内容仅在当前配置合法时使用；命名空间包含appID、token、device、私钥和lyricSource的不可逆摘要，配置变化/移除/失效不得拿旧官方缓存冒充成功。缓存文件不写上述原文、签名或官方清单。
5. 默认 `~/Library/Caches/Likeit/Lyrics`，最多200项、总量20MiB、单项1MiB、绝对有效期30天（读取不续期），按最近访问淘汰；目录0700、普通文件0600，原子写入、带schema版本。损坏/未知schema/过大/过期条目按miss处理；目录不可写或不是目录也不阻塞正常网络结果。不跟随缓存条目符号链接。
6. 空内容、搜索不唯一、网络/权限/解析失败不入缓存，后续重新获取。stop/cancel清理任务和内存，不清持久层；迟到的已取消结果不能写入缓存或回调。
7. 不改变网易/社区的显式选择，不新增自动跨网易与社区兜底，不控制音乐、不改变签名/TCC。用户可退出桌面后删除上述缓存目录以清空，README明确说明。

## 测试接缝

`DesktopLyrics`与`CommunityLyrics`构造器追加 `cacheDirectory: URL? = nil`、`cacheNow: @escaping () -> Date = Date.init`。nil仍是旧的纯内存行为；生产DesktopSession必须为两个provider显式传默认缓存目录。测试使用独立临时目录、合成歌词和URLProtocol，不读用户缓存/凭据、不联网。

共享缓存代码须能被旧冻结swiftc列表编译：可放在已有 `DesktopLyrics.swift`，不要让该文件依赖未被旧官方测试包含的新文件或社区模型。不为测试改已有编译列表。存储格式由开发者决定，保留实际词范围/翻译/来源，不重新猜测词位置。
